4 個 agent 的 pipeline

Spec Planner→ Geometric Architect→ Python Coder→ Skill Loop (QA/修復)

agent 之間只傳精簡的結構化狀態（CADBrief、ArchitectPlan、QA 報告），不塞整段對話歷史 → token 從指數成長變線性。底層用 build123d，串接靠 LangGraph。

核心洞見：瓶頸不是 CAD 能力，而是推理組織沒效率——單 agent 跑 10 題就燒 103M token、1,307 次 API 呼叫。

主要特色

  • 零 token 確定性翻譯器：常見 CAD 操作直接由 plan 翻成 build123d 程式，不呼叫 LLM，只有邊角案例交給 Aider。
  • 白箱可稽核：每個中間產物都落地存檔，可在每次 QA 檢查點介入、覆寫、補需求。
  • 混合路由：4 階段各自挑模型（便宜模型解析、強模型設計、Claude/GPT 修復），可換成自訓本地小模型。
  • print-in-place 可動關節：多實體共存於一個 STEP，留 0.4–1mm 間隙，印完直接會動（球中籠、陀螺儀）。
  • 支援任何 OpenAI 相容端點（OpenAI、DeepSeek、Gemini、本地 Ollama、Claude），非鎖定阿里雲。

安裝 / 使用

  • Python 3.11；conda env create -f environment.yml（Windows 建議走 conda）。
  • 兩種跑法：終端機（10 秒檢查點可中途注入需求／中止）或 Web UI（瀏覽器內 3D 預覽 + 一鍵下載）。
  • 產出：temp_output_0.step／.stl、temp_design_0.py（build123d 原始碼）等。
